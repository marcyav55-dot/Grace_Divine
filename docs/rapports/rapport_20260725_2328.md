## Stack de sécurité choisie (à mettre en place demain)
- **Fail2Ban** : bannissement automatique des IP en cas de force brute
- **CrowdSec** : détection comportementale + liste noire communautaire
- **Nginx Rate Limiting** : limitation du nombre de requêtes par IP
- **HTTPS/SSL** : certificat Let's Encrypt via Certbot
- **Bot Telegram** : notifications instantanées (tentatives bloquées, alertes)

⚠️ Prérequis : nécessite un VPS/serveur de production avec accès root (Nginx + systemd). Ne peut pas être testé dans l'environnement de développement actuel. À clarifier : le VPS est-il déjà choisi/loué ?

## Décision d'hébergement
- **Hébergeur choisi : Railway** (PaaS, pas de gestion Linux/SSH nécessaire)
- Paiement : Visa (déjà disponible)
- Conséquence : la stack sécurité initialement prévue (Fail2Ban, CrowdSec, Nginx Rate Limiting) n'est pas applicable sur Railway (pas d'accès root/SSH)

## Nouvelle stack de sécurité adaptée à Railway
- `django-ratelimit` : limite le nombre de requêtes/tentatives par IP (remplace Nginx Rate Limiting)
- `django-axes` : verrouille un compte/IP après plusieurs échecs de connexion (remplace Fail2Ban/CrowdSec)
- HTTPS/SSL : automatique et gratuit sur Railway, rien à configurer
- Bot Telegram : conservé tel quel, indépendant de l'hébergeur
